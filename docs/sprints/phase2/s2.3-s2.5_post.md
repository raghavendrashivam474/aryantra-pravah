## Sprint-by-Sprint Breakdown

### S2.3 — Message Framing

**Problem:** TCP is a continuous byte stream. `MessageParser` expects exactly one complete message per `byte[]` and rejects trailing bytes. The existing `TransportListener.onDataReceived()` delivers arbitrary TCP read chunks (up to 4096 bytes). There was no mechanism to reconstruct application message boundaries from the raw stream.

**Decision:** Length-prefixed framing envelope (documented in `ADR-003`).

```
[FRAME_LEN: 4 bytes, big-endian unsigned][ENCODED_MESSAGE: FRAME_LEN bytes]
```

**Rationale:** The existing wire format v1 contains internal field lengths (sender, messageId, payload) but no total-message-length prefix. Parsing internal headers to determine frame boundaries would couple framing to message structure. A simple outer envelope keeps the framing layer opaque and independent.

**Deliverables:**

| Component | File | Responsibility |
|-----------|------|----------------|
| `FrameEncoder` | `protocol/FrameEncoder.java` | Wraps `MessageEncoder` output in a 4-byte length prefix. Rejects zero-length and oversized payloads. |
| `FrameDecoder` | `protocol/FrameDecoder.java` | Stateful per-connection byte accumulator. Extracts complete encoded messages from arbitrary TCP chunks. Rejects invalid/negative/oversized length headers. |

**Safety constraints:**
- Maximum frame size: **16 MB** (`16,777,216 bytes`). Prevents uncontrolled memory allocation from malicious length headers.
- Frames with `length <= 0` are rejected immediately with `ProtocolException`.
- Each TCP connection **must** have its own `FrameDecoder` instance. State is never shared.

**Tests added:** 20 (5 encoder + 11 decoder unit + 4 TCP integration)

**Key integration test scenarios:**
- Single complete frame over TCP
- Artificially fragmented frame (split at byte boundary across two TCP writes)
- Three coalesced frames in a single TCP write
- Multi-peer isolation: Peer A's stalled partial frame does not block Peer B's complete message

### S2.4 — Chat Semantics

**Problem:** S2.1 defined `JOIN`, `MESSAGE`, `LEAVE` as vocabulary entries. S2.4 gives them deterministic runtime meaning.

**Deliverables:**

| Component | File | Responsibility |
|-----------|------|----------------|
| `PeerState` | `protocol/PeerState.java` | Enum: `JOINED`, `LEFT`. Transport-agnostic protocol lifecycle state. |
| `ProtocolListener` | `protocol/ProtocolListener.java` | Callback interface: `onPeerJoined()`, `onMessageReceived()`, `onPeerLeft()`. |
| `ProtocolSessionManager` | `protocol/ProtocolSessionManager.java` | State machine enforcing valid message ordering per logical peer. |

**Deterministic state transition policy:**

| Incoming Message | Current State | Action |
|-----------------|---------------|--------|
| `JOIN` | `null` (new) or `LEFT` | Transition to `JOINED`, emit `onPeerJoined` |
| `JOIN` | `JOINED` | **Reject** — `ProtocolException("already in JOINED state")` |
| `MESSAGE` | `JOINED` | Deliver to `onMessageReceived` |
| `MESSAGE` | `null` | **Reject** — `ProtocolException("cannot send MESSAGE before JOIN")` |
| `MESSAGE` | `LEFT` | **Reject** — `ProtocolException("cannot send MESSAGE after LEAVE")` |
| `LEAVE` | `JOINED` | Transition to `LEFT`, emit `onPeerLeft` |
| `LEAVE` | `null` | **Reject** — `ProtocolException("cannot LEAVE without prior JOIN")` |
| `LEAVE` | `LEFT` | **Reject** — `ProtocolException("already in LEFT state")` |

**Design notes:**
- Re-joining after `LEAVE` is explicitly supported.
- Logical identity (`senderId`) is used for all session state — not TCP socket addresses. This preserves transport-agnostic architecture for future Bluetooth/LAN/Internet transports.
- `ProtocolSessionManager` is fully independent of `TcpTransport`, `Socket`, or `InetSocketAddress`.

**Tests added:** 8

### S2.5 — Protocol Validation & Hardening

**Problem:** The pipeline must withstand adversarial and malformed input at every layer without crashing, leaking resources, or disrupting valid peers.

**Deliverables:**

| Test Suite | Tests | Coverage |
|------------|-------|----------|
| `ProtocolValidationTest` | 15 | Framing attacks (zero/negative/oversized lengths), wire parser attacks (bad magic, bad version, unknown type, truncation, trailing bytes), semantic violations (all invalid state transitions) |
| `EndToEndProtocolIntegrationTest` | 2 | Full conversation lifecycle over TCP; adversarial isolation (garbage bytes + 100MB length header + bad magic injected by attacker socket while valid peers communicate concurrently) |

**Key validation properties verified:**
- `FrameDecoder` never allocates uncontrolled memory
- `FrameDecoder` never enters an infinite loop on partial data
- `MessageParser` rejects all 7 categories of malformed wire input
- `ProtocolSessionManager` rejects all 5 categories of invalid state transitions
- A malicious peer sending corrupted frames does not crash the server or disrupt valid peer communication
- Per-connection `FrameDecoder` isolation prevents cross-contamination

**Tests added:** 17

## Final Architecture

```
             Application
                  │
                  ▼
         ProtocolSessionManager  ← S2.4
          (PeerState, semantics)
                  │
                  ▼
              Message
                  │
                  ▼
           MessageEncoder        ← S2.2 (unchanged)
                  │
                  ▼
            FrameEncoder         ← S2.3
                  │
                  ▼
          Transport.send()       ← Phase 1 (unchanged)
                  │
                  ▼
             TcpTransport
                  │
                  ▼
                 TCP
                  │
                  ▼
            TcpTransport
                  │
                  ▼
          TransportListener      ← Phase 1 (unchanged)
           (raw byte chunks)
                  │
                  ▼
            FrameDecoder         ← S2.3 (per-connection)
                  │
                  ▼
           MessageParser         ← S2.2 (unchanged)
                  │
                  ▼
              Message
                  │
                  ▼
         ProtocolSessionManager  ← S2.4
```

## What Was Deliberately NOT Built

Per the Phase 2 scope boundary, the following were explicitly excluded and remain future work:

- Accounts, authentication, persistent identities
- Delivery receipts, retries, offline storage, message history
- Custom encryption, key exchange, forward secrecy
- Cover traffic, traffic shaping, metadata obfuscation
- Bluetooth, LAN discovery, Internet transport, adaptive routing
- Android or any platform-specific integration
- AI or cloud services
