# Sprint S3.1 — Peer Identity

## Objective
Establish a formal, immutable logical identity model (PeerId) for Pravah peers, completely decoupled from physical transports, sockets, ports, or connection IDs.

## Existing Baseline
- Phase 2 complete (0.3.0 baseline with 87/87 tests passing).
- Protocol session manager used string-based senderId on messages.

## Implemented Capability
- **PeerId** (com.aryntra.pravah.peer.PeerId):
  - Invariant validation (non-null, non-blank, automatic trimming).
  - Deterministic value-based equality and hash code semantics.
  - Factory methods: PeerId.of(String) and PeerId.generate() (UUID-backed).
  - Explicit string representation (PeerId[<value>]).

## Files Added
- src/main/java/com/aryntra/pravah/peer/PeerId.java
- src/test/java/com/aryntra/pravah/peer/PeerIdTest.java

## Files Modified
- None (zero mutations to existing Phase 0/1/2 classes).

## API & Contract Changes
- Introduced PeerId in com.aryntra.pravah.peer.

## Tests Added
- PeerIdTest: 13 tests covering creation, validation, trimming, equality, hashing, random generation uniqueness, and type checks.

## Architectural Decisions
- PeerId represents *WHO* is communicating, strictly decoupled from *HOW*.
- Authentication, cryptography, and persistence are deliberately deferred.

## Out of Scope
- Cryptographic keys, peer authentication, persistent identity databases.

## Known Limitations
- Purely in-memory representation.
