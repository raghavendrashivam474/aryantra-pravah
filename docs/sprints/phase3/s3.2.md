# Sprint S3.2 — In-Memory Peer Registry

## Objective
Create a thread-safe, in-memory peer registry to track known peers and maintain the mapping between logical PeerId and active transport connection IDs.

## Existing Baseline
- S3.1 complete (PeerId established, 100 tests passing).

## Implemented Capability
- **PeerRecord** (com.aryntra.pravah.peer.PeerRecord):
  - Immutable record binding PeerId with an optional/nullable transport connectionId.
  - Helpers: connected(peerId, connId), disconnected(peerId), isConnected(), optionalConnectionId(), withConnectionId(newConnId).
- **PeerRegistry** (com.aryntra.pravah.peer.PeerRegistry):
  - Concurrent in-memory store backed by ConcurrentHashMap.
  - Operations: egister(record), egister(peerId, connId), lookup(peerId), lookupByConnectionId(connId), contains(peerId), emove(peerId), llPeers(), size(), clear().
  - Deterministic duplicate handling: updates/replaces existing record to support peer reconnections cleanly.

## Tests Added
- PeerRegistryTest: 13 tests covering registration, lookups, duplicate updates, reverse connection lookups, removals, unmodifiable views, record invariants, and multi-threaded concurrency safety.

## Architectural Decisions
- Replaced records update in place rather than rejecting to seamlessly support reconnections.
- Decoupled from transport lifecycle: registry removal does not close transport connections directly.

## Out of Scope
- Disk persistence, distributed sync, LAN discovery population.

## Known Limitations
- Ephemeral in-memory storage.
