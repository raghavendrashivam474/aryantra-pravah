### 3.2 Sprint S0.2 — Architecture Contracts

**Objective:** Translate the locked architectural direction (hybrid micro-components + strict contracts) into explicit, documented engineering boundaries. No networking implementation.

**Deliverables:**
- `docs/architecture/architecture.md` documenting:
  - Project purpose and long-term P2P vision
  - Hybrid micro-component and strict-contract principles
  - Dependency direction: `Application → Core → Protocol → Transport → Network`
  - Transport boundary diagram (Core decoupled from TCP/BLE/LAN)
  - Message/protocol boundary (raw bytes → framed data → application message)
  - Explicitly deferred capabilities (BLE, adaptive routing, Android, DHT)
- `docs/architecture/ADR-001-hybrid-micro-components.md` recording:
  - **Context:** Need to prevent monolithic coupling while avoiding over-engineered abstractions
  - **Decision:** Small cohesive components with strict interface contracts; lower layers agnostic of higher-layer semantics
  - **Consequences:** Improved testability and extensibility at the cost of slight initial interface ceremony

**Verification:**
- All S0.1 functionality preserved (build and tests still pass)
- No speculative component explosion or unnecessary interfaces introduced

**Commit:** `de6647d` — `docs(architecture): define component boundaries and ADR-001`

### 3.3 Sprint S0.3 — Core Runtime Foundation

**Objective:** Establish a minimal application lifecycle, configuration mechanism, error-handling convention, and structured logging — still without any networking.

**Deliverables:**
- `LifecycleState.java` — Enum defining states: `INITIALIZED`, `STARTING`, `RUNNING`, `STOPPING`, `STOPPED`, `FAILED`
- `PravahConfig.java` — Immutable Java 21 `record` holding `appName`, `environment`, `port` with validation (port range 1024–65535) and a `defaultConfig()` factory
- `PravahException.java` — Base runtime exception for consistent error handling across the system
- `PravahRuntime.java` — Core runtime engine managing:
  - Thread-safe state transitions via `AtomicReference<LifecycleState>`
  - Synchronized `start()` and `stop()` lifecycle methods
  - `java.util.logging.Logger` integration for structured lifecycle events
  - Clean shutdown hook registration in `Main.java`
- `PravahRuntimeTest.java` — 4 unit tests covering:
  - Initial state verification
  - Full lifecycle transition (`INITIALIZED → RUNNING → STOPPED`)
  - Double-start guard (throws `PravahException`)
  - Invalid port configuration rejection

**Verification:**
- `mvn clean test` → 5/5 tests passing (1 smoke + 4 runtime)
- `java -jar target/pravah-0.1.0-SNAPSHOT.jar` produces clean lifecycle log:
  ```
  INFO: Pravah starting [Aryntra-Pravah | env=development]
  INFO: Pravah running
  INFO: Pravah stopping
  INFO: Pravah stopped
  ```
- No networking code introduced

**Commit:** `2f12cf0` — `feat(core): implement lifecycle state, config, and runtime foundation (S0.3)`

### 3.4 Sprint S0.4 — Architecture Verification

**Objective:** Experimentally verify that the documented architecture is practically usable before entering TCP implementation. Confirm that consumers can depend on contracts without coupling to concrete implementations.

**Deliverables:**
- `Transport.java` — Minimal strict contract interface exposing:
  - `getName()`, `start()`, `stop()`, `isRunning()`
  - `send(String destinationId, byte[] payload)`
  - `setListener(TransportListener listener)`
- `TransportListener.java` — Functional interface for receiving raw frame data: `onDataReceived(String senderId, byte[] payload)`
- `TransportContractVerificationTest.java` — Contract verification experiment containing:
  - `InMemoryTransport` test double implementing the `Transport` contract purely in memory (no sockets)
  - Test proving a consumer can interact strictly through the `Transport` interface
  - Verification of lifecycle control and asynchronous data delivery via listener callback

**Dependency Direction Audit:**
- Automated scan confirmed zero import leaks from `core` package into `java.net.Socket`, `server`, or `client` packages
- `Transport` contract has no dependencies on application-layer semantics

**Verification:**
- `mvn clean test` → 6/6 tests passing (1 smoke + 4 runtime + 1 contract verification)

- Architecture documentation reviewed; no changes required

## 6. What Was Explicitly NOT Implemented (Per Brief)

The following were intentionally deferred and do not exist in the codebase:

- TCP server/client (`ServerSocket`, `Socket`)
- Protocol parser or wire format
- Message model or application commands (JOIN, MESSAGE, LEAVE)
- Peer identity, discovery, or registry
- Bluetooth / BLE transport
- LAN discovery or UDP transport
- Internet routing or adaptive path selection
- Reliability layer or offline queue
- Mobile application or Android integration
- Chat UI or room management

## 7. Next Steps — Phase 1 Preview

With the foundation verified and tagged at `v0.0.0-s0`, Phase 1 will introduce the first concrete transport implementation:

- **S1.1 — TCP Foundation:** `ServerSocket` → `accept()` → `Socket` lifecycle
- **S1.2 — TcpTransport:** Concrete implementation satisfying the existing `Transport` contract
- **S1.3 — CLI Client/Server:** Java CLI demonstrating bidirectional TCP communication through the Pravah runtime

The `Transport` contract established in S0.4 will be the integration seam. The `PravahRuntime` lifecycle from S0.3 will orchestrate startup and shutdown. No architectural changes are anticipated.
