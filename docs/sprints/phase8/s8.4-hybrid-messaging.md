# Sprint 8.4: Hybrid Messaging via Composite Transport

## Objective
Enable Pravaah's application and peer-routing layers to seamlessly route framed protocol messages over multiple underlying physical/virtual transports (TCP and Bluetooth RFCOMM) via a single unified `Transport` abstraction without leaking transport-specific mechanisms upward.

## Architecture & Implementation

### 1. Unified Delegation (`CompositeTransport`)
`com.aryntra.pravah.transport.CompositeTransport` implements the standard `Transport` interface:
- **Transport Registry:** Aggregates arbitrary child `Transport` implementations (`TcpTransport`, `BluetoothRfcommTransport`, etc.).
- **Dispatch Strategy:** Dispatches `send(destinationId, payload)` based on:
  1. Active connection tracking cache (`connectionTransportMap`), populated dynamically as connections open/receive data.
  2. Scheme prefixes (e.g., `bt:*`, `bluetooth://*`, `tcp://*`).
  3. Default fallback to the primary transport for standard socket addresses (`/IP:PORT`).
- **Unified Lifecycle:** Idempotently starts and stops all registered child transports.
- **Aggregated Listener:** Funnels child connection open, close, and raw frame data reception into a single `TransportListener` stream without dropouts or duplicated events.

### 2. Upward Layer Isolation
- `PeerRouter` continues sending via `send(PeerId, Message)` and `resolveConnectionId(PeerId)`.
- `PeerConnectivityRegistry` paths (`tcp` and `bluetooth`) map cleanly into connection IDs dispatched by `CompositeTransport`.
