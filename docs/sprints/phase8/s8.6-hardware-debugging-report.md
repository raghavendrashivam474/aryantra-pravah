# Phase 8: Real-World Hardware Debugging & Stabilization Report

**Date:** 2026-10-02
**Context:** S8.6 Real-World Android Validation
**Devices:** Android Phone (Device A) and Android Tablet (Device B)

## Overview
Moving Pravaah's hybrid multi-path architecture from JVM-based simulated RFCOMM to physical Android hardware exposed several critical edge cases regarding network anomalies, Android OS constraints, and asynchronous state synchronization. This document outlines the problems observed during physical testing and the surgical architectural fixes applied to achieve stability.

---

## 1. Bluetooth MAC Masking & Adapter Isolation
**Symptom:** JVM unit tests crashed with `BluetoothAdapter not mocked`. On physical hardware, hardcoded Bluetooth MAC addresses (`02:00:00:00:00:01`) failed with `read failed, socket might closed`.
**Root Cause:** 
- Android `android.jar` throws exceptions when framework APIs are called on a desktop JVM.
- Modern Android OS hides real MAC addresses behind `02:00...` for privacy. RFCOMM sockets require the exact physical MAC address of a bonded device.
**Resolution:**
- **JVM:** Enabled `isReturnDefaultValues = true` in Gradle and wrapped `BluetoothAdapter.getDefaultAdapter()` in a `try/catch` returning `null`, allowing the transport to gracefully degrade to passive mode during PC unit testing.
- **Hardware:** Implemented a dynamic Paired Device Chooser in `DiagnosticActivity` utilizing `adapter.bondedDevices` to fetch and connect to actual, physical MAC addresses.

---

## 2. Multi-Path Duplication & Accumulation
**Symptom:** The diagnostic topology displayed 3–4 duplicate TCP paths for the same peer (e.g., `/10.177.67.157:33303` and `10.177.67.157:33303`).
**Root Cause:** 
- `TcpTransport` yields remote socket addresses with a leading slash (`/IP`). Manual connections used just `IP`.
- `PeerPresenceBridge` created a unique `PathId` for every variation of a connection string, leading to unchecked path accumulation.
**Resolution:**
- **Connection Normalization:** Added `cleanConnId()` to strip leading slashes universally.
- **Strict Scheme Deduplication:** Updated `PeerPresenceBridge.activatePath()` to use canonical deterministic path IDs (`path:<peerId>:tcp` and `path:<peerId>:bluetooth`). When a new connection arrives, it updates the *existing* scheme's path instead of blindly appending a new one.

---

## 3. Orphaned Bluetooth Peer Identity (`remote-bt-node`)
**Symptom:** If a user connected via Bluetooth *before* UDP discovery resolved the real `PeerId`, the Bluetooth path bound to a dummy ID (`remote-bt-node`), while the TCP path bound to the real ID (`android-53f2e10b`), splitting one physical device into two logical peers.
**Root Cause:** 
- Bluetooth connections initiated manually lacked cryptographic/protocol context of the remote peer's identity until a `JOIN` was sent.
**Resolution:**
- **Auto-JOIN Handshake:** Updated `PravahAndroidMessagingManager` to automatically transmit a protocol `JOIN` immediately upon opening a Bluetooth socket.
- **Peer Merge/Migration:** Added `cleanOrphanedBtNode(authenticatedPeer)`. When an authenticated `JOIN` arrives over the BT socket, the system migrates the active BT path to the real `PeerId` and destroys the orphaned `remote-bt-node` record.

---

## 4. Dynamic Port Changes on App Restart
**Symptom:** Restarting the app on Device B caused the OS to assign a new dynamic TCP port (e.g., `46083` → `34899`). Device A failed to connect because it cached the old port.
**Root Cause:** `PeerPresenceBridge.onCandidateDiscovered` ignored discovery packets for already-known peers.
**Resolution:**
- Updated the discovery listener so that every incoming UDP beacon overwrites the `CANDIDATE` path's `EndpointAddress`. This guarantees the candidate path always points to the most recently broadcasted port.

---

## Conclusion
The application of these fixes resulted in perfect synchronization. The system now guarantees:
1. Exactly **one logical PeerId** per device.
2. Exactly **one TCP path** and **one Bluetooth path** managed side-by-side.
3. Completely seamless outbound route failover (e.g., `TCP -> BT`) without dropping the session layer.
