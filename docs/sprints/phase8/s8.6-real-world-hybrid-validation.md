# Sprint 8.6: Real-World Android Hybrid Validation & Multi-Path Diagnostics

## Objective
Extend Pravaah's Android integration with native Bluetooth RFCOMM transport capabilities, unified composite routing, multi-path candidate management, and real-time multi-path observability in the Diagnostic Activity.

## Architecture & Implementation

### 1. Native Android RFCOMM Transport (`AndroidBluetoothRfcommTransport`)
- Implements `com.aryntra.pravah.transport.Transport`.
- Uses Android `BluetoothAdapter`, `BluetoothServerSocket`, and `BluetoothSocket` over standard SPP UUID (`00001101-0000-1000-8000-00805F9B34FB`).
- Background worker threads manage non-blocking accept loops and stream reads.
- Connection namespace: `bt:{MAC}`.
- Capabilities: Reliable, connection-oriented, unicast stream.

### 2. Permissions Integration (`AndroidManifest.xml`)
- Legacy Bluetooth permissions (API 26–30): `BLUETOOTH`, `BLUETOOTH_ADMIN`, `ACCESS_FINE_LOCATION`.
- Modern Bluetooth runtime permissions (API 31–34+): `BLUETOOTH_SCAN` (`neverForLocation="true"`), `BLUETOOTH_ADVERTISE`, `BLUETOOTH_CONNECT`.

### 3. Android Hybrid Messaging Coordinator (`PravahAndroidMessagingManager`)
- Houses `CompositeTransport` aggregating `TcpTransport` and `AndroidBluetoothRfcommTransport`.
- Supports both `connectToTcp` and `connectToBluetooth` registering active paths into `PeerConnectivityRegistry`.
- Applies `PathSelectionPolicy.preferSchemes("tcp", "bluetooth", "bt")` for seamless outbound routing.

### 4. Diagnostic Dashboard Multi-Path Tree (`DiagnosticActivity`)
- Visualizes real-time multi-path hierarchy for each peer:

```text
Peer: android-a1b2c3d4
├── [TCP] path-tcp-192.168.1.50:8080 -> ● ACTIVE (192.168.1.50:8080)
├── [BLUETOOTH] path-bt-02:00:00:00:00:01 -> ● ACTIVE (bt:02:00:00:00:00:01)
└── [DISPATCH ROUTE]: 192.168.1.50:8080
```

- Interactive Controls: `CONNECT TCP`, `CONNECT BT`, `DROP TCP` (simulates immediate path failover), and `SEND`.
