# S8.3 — Hybrid Discovery & Addressing

**Status:** Completed
**Baseline commit:** f0ee5c3

## Overview

Sprint S8.3 evolves Pravaah from single-transport LAN discovery toward true hybrid, multi-transport discovery and addressing without violating existing Phase 6 & Phase 7 invariants.

## Architectural Deliverables

1. **`DiscoveredAddressCandidate`:**
   - Universal value record representing reachability candidates across arbitrary transport mechanisms (`tcp`, `bluetooth`, etc.).
   - Computes canonical deterministic path IDs: `path:{peerId}:{transport}:{host}:{port}`.
   - Provides safe transformation into `ConnectivityPath` with `CANDIDATE` initial state.

2. **`BluetoothPeerDiscovery`:**
   - Simulates Bluetooth inquiry / RFCOMM service announcement and candidate emission in the JVM runtime.
   - Decoupled from physical sockets, ensuring zero Android framework dependencies in the core module.

3. **`PeerPresenceBridge` Extensions:**
   - Extended with `onCandidateDiscovered(...)` for universal candidate intake.
   - Preserves existing `LanPeerDiscovery` and `onPeerDiscovered(DiscoveredPeer)` without modification.
   - Enforces candidate deduplication / idempotency.
   - Supports multi-path lifecycle (`handleConnectionClosed`) allowing individual active paths to deactivate without dropping other active paths or destroying the logical peer identity.

## Invariant Verification

- **Peer identity != connection identity:** Maintained. Single `PeerId` aggregates multiple heterogeneous paths.
- **Discovery != connectivity:** Discovery generates `CANDIDATE` paths, never `ACTIVE`.
- **Destination != transport:** Messages are addressed to `PeerId`, while the connectivity registry tracks multiple transport paths.
