# Sprint 8.5: Multi-Path Operation & Path Selection Policies

## Objective
Enable Pravaah to maintain multiple simultaneous active transport paths (e.g. Wi-Fi TCP and Bluetooth RFCOMM) for a single logical peer, and provide deterministic, policy-driven path selection, transparent failover upon path degradation, and automatic recovery without peer identity duplication or protocol session disruption.

## Architecture & Implementation

### 1. Deterministic Path Selection (`PathSelectionPolicy`)
- Interface: `com.aryntra.pravah.connectivity.PathSelectionPolicy`
  - `Optional<ConnectivityPath> selectPath(PeerId destination, List<ConnectivityPath> activePaths)`
- **Policies:**
  - `defaultPolicy()` / `byPathId()`: Deterministic lexicographical ordering by `PathId.value()` (100% Phase 6 backward compatible).
  - `preferSchemes(String... preferredSchemes)`: Prioritizes specified transport schemes (e.g. `tcp` over `bluetooth`), breaking ties deterministically by `PathId`.

### 2. Multi-Path Peer Routing (`PeerRouter`)
- Integrates `PathSelectionPolicy` into path resolution without modifying application messaging APIs.
- Preserves single `PeerId` representation in `PeerConnectivityRegistry` across multiple paths.
- Instant failover: Deactivation of the primary active path shifts next outbound dispatch immediately to the next highest-priority active path.
- Path recovery: Transitioning an inactive path back to `ACTIVE` restores it as a candidate, re-promoted according to the selection policy.
